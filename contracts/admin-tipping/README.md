# Isolated QA tipping candidates

This standalone workspace does not modify the shared Tipping/Funding TypeID cells or the original contract crates. It contains fresh Tip/Funding candidates and a copy of the QA-owned ProtocolLock with optional `qa-admin-tipping`. The original on-chain layout is retained. Fresh Funding uses a minimal entry without SSRI/legacy classifier; its known Campaign settings/review branch binds the actual input campaign full type, owner lock and protocol/configured scripts, while the real CampaignType/ProtocolLock continue enforcing reward/deduction/role rules. Unknown methods are rejected. These are development candidates, not deployed capabilities.

`policy` links the AdminRegistry's strict binary financial prefix. `CKBOOST_ADMIN_REGISTRY_TYPE_HASH` must be a nonzero exact32byte full registry state Type hash at compile time. Missing anchor fails closed. Initial test-only artifacts used synthetic93330b9c…81f5 and remain archived. Current release candidates and VM fixtures bind the reviewed unsigned plan's full Registry state Type hash97e23b14…9690 (code12a5aa79…39d5); this is planned, not deployed or live. The final batch must independently confirm the exact code/state before activation.

V2 SSRI interface: `CKBoostTipping.update_tipping(tx, tippingData, declaredAtMsLE8)`. Builder creates exactly two recipe arguments: output-data reference (`arg_type=2`, exact u32LE output index), signed application-time declaration (`arg_type=0`, exact u64LE milliseconds). First valid recipe in witness order wins. No extra time witness or Molecule schema change.

Rules: proposer remains current Admin/Organizer; first approval must be current platform Admin; later approver is current Admin or exact pinned registry approver (Organizer role alone grants no approval). Append one distinct supporter with immutable prefix/payload. Actor must have a plain empty native input and strict net capacity spend across all same-lock inputs/outputs, including typed capacity. Final status is automatic at the registry CKB thresholds. Mint and asset quantities are exact Uint128; accepted UDT full scripts are compared without shortened classifier labels. Pool total capacity decreases by exactly the CKB reward; depleted token-cell storage remains in the pool. Recipient token net amounts and global Points mint are exact. NFTs remain unsupported.

Expiration is an explicitly signed application-time policy, not a trustless consensus clock: the client must verify fresh latest-header/time before signing, and the contract checks declaration format, no future creation, overflow, deadline and final granted_at equality.0 explicitly means Never. CKB scripts cannot independently obtain current inclusion time. See RFC0017 (since is a lower-bound lock) and RFC0022 (header deps identify selected headers), not a timestamp oracle. This limitation must remain visible in the final batch preview.

Native policy tests and actual-binary VM tests are separate. The latter use unchanged publicly verified fcb4 Points bytes and explicitly synthetic ALWAYS_SUCCESS wallet fixtures; they do not prove a real wallet signature, public-chain inclusion or deployment. Actual ACP wallet coverage is separate.

Activation must fail closed until fresh QA Tip/Funding/Registry code and state, QA-only ProtocolLock upgrade, exact current protocol code configuration, reviewed runtime lineage and SDK options all match. No normal-mode environment flag enables this feature. Existing QA Campaign/User/Points/claim pools are not recreated. Before switching singular Tip/Funding code identities, inventory and require no pending legacy Tip or legacy pool cells; arbitrary retyping/migration of legacy records is not supported by their old validators. Keep all historical evidence unchanged.

Time model references: [CKB RFC0017](https://github.com/nervosnetwork/rfcs/blob/master/rfcs/0017-tx-valid-since/0017-tx-valid-since.md) and [RFC0022](https://github.com/nervosnetwork/rfcs/blob/master/rfcs/0022-transaction-structure/0022-transaction-structure.md).
